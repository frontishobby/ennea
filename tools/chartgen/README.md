# chartgen — 채보 생성기 (M3)

음원 WAV 하나에서 easy / normal / hard 채보를 만든다. 오프라인 Node 스크립트고,
결과는 `static/charts/<chartHash>.json` 으로 커밋한다. 런타임 생성은 하지 않는다 —
브라우저·CPU 간 부동소수점 차이가 1v1 공정성을 깬다 (PLAN §6).

```bash
npm run chart -- out/hard-dance/hard-dance-12345.wav --slug neon-drift --preview
npm run chart:selftest          # 합성 신호로 파이프라인 검증
npm run check                   # svelte-check + tsc -p tools/chartgen
```

## 파이프라인 (PLAN §6 그대로)

| 단계 | 파일 | 내용 |
|---|---|---|
| ① STFT | `dsp.ts` | 2048 / hop 512 / Hann. 48kHz 에서 10.7ms 해상도 |
| ② 로그 압축 | `dsp.ts` | `log(1 + 1000·|X|)`. 빼면 조용한 인트로에서 노트가 안 나온다 |
| ③ Spectral flux | `dsp.ts` | 대역별, **증가분만**. 저역 20~250 / 중역 250~2k / 고역 4k~16k |
| ④ 적응형 임계값 | `onset.ts` | `δ + α·median(±0.3s)`. 고정 임계값 금지 |
| ⑤ 피크 피킹 | `onset.ts` | 국소 최대 + 30ms 최소 간격 + **감쇠 마스크** |
| 대역 배정 | `analyze.ts` | ±25ms 안 검출을 한 타격으로 묶고 **지배 대역**이 가져간다 |
| ⑥ BPM + 스냅 | `tempo.ts` | 자기상관 + 하모닉 콤 + 포물선 보간. 원형 평균으로 위상. 16분음표 스냅 |
| ⑦ 타입 배정 | `build.ts` | 저역→scroll, 중역→cursor, 고역→click |
| ⑧ 커서 배치 | `build.ts` | **M3: 이동 예산 안에서 랜덤.** 패턴 어휘·D4·관성은 M4 |
| ⑨ 제약 | `build.ts` | 스크롤 ≥200ms, 커서 ±50ms 스크롤 금지, 스크롤 직후 예산 절반 |

PLAN 에 없던 두 단계가 필요했다. 합성 신호로 돌려보니 바로 드러났다.

**감쇠 마스크** — 킥의 피치 스윕 꼬리와 스네어 노이즈의 미세 봉우리는 임계값은 넘지만
직전 타격의 몇 분의 일이다. 봉우리 직후 그 세기의 0.6배에서 시작해 τ=80ms 로 감쇠하는
문턱을 추가로 건다. 없으면 킥 하나가 노트 둘이 된다.

**지배 대역** — 킥의 클릭 트랜지언트는 고역까지 번지고 스네어 노이즈는 저역까지 내려온다.
대역마다 따로 잡으면 타격 하나가 노트 셋이 된다. ±25ms 안의 검출을 묶어 sf/thr 비율이
가장 큰 대역이 가져가고, 다른 대역은 비율이 충분할 때(진짜 동시 타격)만 같이 남긴다.
부작용: 킥과 같이 치는 앞박 하이햇은 킥에 흡수된다. 뒷박만 클릭이 되는데, 리듬게임
채보로는 오히려 자연스럽다.

## 난이도

같은 음원, 같은 온셋. `build.ts` 의 `PARAMS` 가 거른다.

| | easy | normal | hard |
|---|---|---|---|
| 그리드 | 8분음표 | 16분음표 | 16분음표 |
| 온셋 세기 (sf/thr) | ≥ 1.6 | ≥ 1.25 | ≥ 1.0 |
| 같은 타입 최소 간격 (비트) | 커서 1 / 클릭 1 / 스크롤 2 | ½ / ½ / 1 | ¼ / ¼ / ½ |
| 비트당 최대 노트 | 1 | 2 | 4 |
| 커서 예산 `v_max` (칸/초) | 2.5 | 4.5 | 7.5 |
| 클릭-커서 겹침 | 100ms 금지 | 60ms 금지 | 허용 |

간격을 초가 아니라 **비트 단위**로 두는 이유: 118 BPM 과 174 BPM 에서 같은 "음악적"
밀도가 되게 하기 위해서다. 절대 난이도 차이는 `songs.json` 의 `level`(1~10) 이 진다 —
DnB 의 easy 는 synthwave 의 normal 쯤 된다.

`v_max` 는 실측 대상이다 (PLAN §15). 지금 값은 추정치.

## 결정성

- 시드 = `hash(songHash | difficulty | generator)`. songHash 는 WAV 파일 바이트의 sha256
- 채보 파일은 `canonicalize()` 의 정규 직렬화 그대로라 **`sha256(파일) == chartHash`**
- `t` 는 정수 ms. 부동소수점이 들어가면 `canonicalize` 가 throw 한다
- 셀프테스트가 "같은 입력 → 같은 채보"와 "다른 곡 → 다른 배치"를 확인한다

알고리즘을 바꾸면 `GENERATOR` 를 올린다. 해시가 바뀌므로 새 채보 = 새 기록 슬롯이고
옛 기록은 오염되지 않는다 (PLAN §8).

## 귀로 검증

```bash
npm run chart -- song.wav --slug my-song --preview
# → tools/chartgen/work/my-song-hard.wav
```

원곡 위에 노트 타입별 소리를 얹는다: cursor 1.2kHz 톡, click 3kHz 틱, scroll 250Hz 툭.
**M3 의 목적은 이걸 듣고 "노트가 음악에 맞게 떨어지는가"를 확인하는 것이다** (PLAN §13).
이게 안 맞으면 나머지가 무의미하다.

`--dump` 를 주면 `work/<slug>-onsets.csv` 에 온셋 전체(시각·대역·비율)가 떨어진다.

## 셀프테스트

`selftest.ts` 가 150 BPM 합성 드럼(킥 1·3박, 스네어 2·4박, 햇 8분음표, 조용한 8박 인트로,
패드, 노이즈 바닥)을 만들어 정답과 대조한다. 확인하는 것:

- BPM ±0.5, 비트 위상 ±15ms
- 대역별 재현율·정밀도·검출 bias (bias 가 `DETECTION_OFFSET_SEC` 의 근거다)
- 채보 규칙 위반 0, 밀도 단조 증가, 결정성

정밀도 바닥은 느슨하다. 스네어는 광대역이라 저역·고역에도 *정직하게* 잡히고, 그건
`build.ts` 의 겹침 규칙이 거른다. 여기서 잡는 건 "타격 하나가 여럿으로 쪼개지는" 회귀다.

`--wav` 를 주면 `work/` 에 합성 신호와 클릭 트랙을 써준다.

## 한계 (v1)

- **템포 고정.** 드리프트·변박 없음. AI 생성 EDM 은 기계적으로 정확해서 괜찮다
- **다운비트를 모른다.** 섹션 경계(8마디)는 비트 위상에서 시작할 뿐 마디 첫 박 보장이 없다
- 커서 배치가 랜덤이라 "아까 그거다" 하는 반복 인지가 없다 — M4
- `level` 은 nps 와 커서 속도로 만든 추정치. 손으로 고쳐도 된다
- 실제 곡으로 `δ`·`α`·`v_max` 를 다시 잡아야 한다 (PLAN §15)
