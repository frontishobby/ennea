# chartgen — 채보 생성기 (M3)

음원 WAV 하나에서 easy / normal / hard 채보를 만든다. 오프라인 Node 스크립트고,
결과는 `static/charts/<chartHash>.json` 으로 커밋한다. 런타임 생성은 하지 않는다 —
브라우저·CPU 간 부동소수점 차이가 1v1 공정성을 깬다 (PLAN §6).

```bash
npm run chart -- out/hard-dance/hard-dance-12345.wav --slug neon-drift --preview
npm run chart:selftest          # 합성 신호로 파이프라인 검증
npm run check                   # svelte-check + tsc -p tools/chartgen
```

## 파이프라인 (PLAN §6 그대로)

| 단계 | 파일 | 내용 |
|---|---|---|
| ① STFT | `dsp.ts` | 2048 / hop 512 / Hann. 48kHz 에서 10.7ms 해상도 |
| ② 로그 압축 | `dsp.ts` | `log(1 + 1000·|X|)`. 빼면 조용한 인트로에서 노트가 안 나온다 |
| ③ Spectral flux | `dsp.ts` | 대역별, **증가분만**. 저역 20~250 / 중역 250~2k / 고역 4k~16k |
| ④ 적응형 임계값 | `onset.ts` | `δ + α·median(±0.3s)`. 고정 임계값 금지 |
| ⑤ 피크 피킹 | `onset.ts` | 국소 최대 + 30ms 최소 간격 + **감쇠 마스크** |
| 대역 배정 | `analyze.ts` | ±25ms 안 검출을 한 타격으로 묶고 **지배 대역**이 가져간다 |
| ⑥ BPM + 스냅 | `tempo.ts` `grid.ts` | 전역 BPM 은 자기상관. 스냅은 **지역 비트 그리드**(아래) |
| 대역 적합도 | `analyze.ts` | 지역 그리드 정렬률이 확률+0.2 미만인 대역은 노트 타입을 **생략** |
| 구간 신뢰도 | `grid.ts` `build.ts` | 창별 (정렬률 − 귀무 기준선). 낮은 구간은 비트당 1개, 센 타격만, **스냅 안 함** |
| 구간별 분할 | `grid.ts` | 창마다 16분·12분(셋잇단) 격자를 둘 다 맞춰 더 잘 설명하는 쪽을 쓴다 |
| ⑦ 타입 배정 | `build.ts` | 저역→scroll, 중역→cursor, 고역→click |
| ⑧ 커서 배치 | `build.ts` | **M3: 이동 예산 안에서 랜덤.** 패턴 어휘·D4·관성은 M4 |
| ⑨ 제약 | `build.ts` | 스크롤 ≥200ms, 커서 ±50ms 스크롤 금지, 스크롤 직후 예산 절반 |

PLAN 에 없던 단계들이 필요했다. 둘은 합성 신호에서, 둘은 첫 실제 곡에서 드러났다.

**감쇠 마스크** — 킥의 피치 스윕 꼬리와 스네어 노이즈의 미세 봉우리는 임계값은 넘지만
직전 타격의 몇 분의 일이다. 봉우리 직후 그 세기의 0.6배에서 시작해 τ=80ms 로 감쇠하는
문턱을 추가로 건다. 없으면 킥 하나가 노트 둘이 된다.

**지배 대역** — 킥의 클릭 트랜지언트는 고역까지 번지고 스네어 노이즈는 저역까지 내려온다.
대역마다 따로 잡으면 타격 하나가 노트 셋이 된다. ±25ms 안의 검출을 묶어 sf/thr 비율이
가장 큰 대역이 가져가고, 다른 대역은 비율이 충분할 때(진짜 동시 타격)만 같이 남긴다.
부작용: 킥과 같이 치는 앞박 하이햇은 킥에 흡수된다. 뒷박만 클릭이 되는데, 리듬게임
채보로는 오히려 자연스럽다.

**지역 비트 그리드** (`grid.ts`) — 첫 실제 곡(ACE-Step, future-core)에서 전역 고정 그리드의
16분음표 정렬률이 36% 였다. 확률이 34% 다. 디퓨전 출력은 메트로놈이 없어서 128초 동안
±1~2% 흔들리고, 평균 BPM 이 맞아도 고정 그리드는 뒤로 갈수록 노트를 음악 밖으로 민다.
8초 창(4초 간격)마다 간격은 노벨티 자기상관으로, 위상은 **정렬률을 직접 최대화하는
브루트포스**로 맞춘다 — 원형평균은 앞박·뒷박·16분을 한 각도로 뭉개서 46% 에 그쳤다.
창 사이는 간격을 선형 보간하며 그리드 점을 걸어 나가고 앵커마다 절반씩 당긴다.
결과가 채보의 `beats` 목록이다. 실측: 36% → mid 65%, high 71%. 셀프테스트의 150→154
램프에서 비트 추적 오차 p90 15ms.

**대역 적합도 게이트** — 같은 곡의 저역은 세 가지 방법 모두에서 확률 수준(32~42%)이었다.
에너지 엔벨로프에 비트 주기가 없고, 킥 후보 간격의 9% 만 P 근처였다. 프롬프트에
"four on the floor kick" 을 써도 모델은 베이스 벽을 만들었다. 그리드에 안 붙는 온셋을
스냅하면 노트가 음악 밖으로 밀려나고 그건 소리로 바로 들리므로, **그 대역의 노트
타입은 만들지 않고 보고한다.** 커서 대역(mid)이 탈락하면 곡 자체가 부적합하다고 경고한다.

**구간별 리듬 신뢰도** — 대역 게이트를 넘은 mid/high 도 곡 전체가 고르게 리듬적이진 않다.
future-core 의 60~96초 브레이크다운은 귀로 확실히 틀렸는데 첫 게이트는 통과시켰다. 원인은
통계적 실수였다: 창의 정렬률은 위상 100개를 훑어 **최대**를 고른 값인데 기준선을 위상 하나짜리
확률(2·tol/step ≈ 39%)로 잡았다. 무작위 온셋도 최적 위상을 고르면 ~50% 가 나온다.
그래서 창마다 같은 개수의 온셋을 무작위 시각으로 바꿔 똑같이 최적화한 정렬률(5회 평균,
결정적 PRNG)을 **귀무 기준선**으로 쓴다. 여유 = 실제 − 귀무. 그러자 귀와 숫자가 갈렸다:
귀로 맞는 창 32~53%, 틀린 창 5~22%. 사이 빈틈에 WEAK 0.15 를, 위에 SOLID 0.30 을 둔다.
약한 구간에선 세기 문턱을 3배로 올리고 스냅을 끈다 — 못 믿는 그리드로 노트를 옮기면 더 틀린다.
`main.ts` 가 `박자 흐린 구간 18s / 128s — 67~70s, …` 로 찍는다. 리듬게임은 브레이크다운을
원래 노트를 비워서 처리한다.

**구간별 분할 (셋잇단)** — 약한 구간에서 살아남는 노트를 뜯어보니 조용한 가짜가 아니라
트랙에서 가장 센 축의 타격이었다 (sf 0.70 vs 트랙 중앙 0.46). 크고 분명한데 16분 격자에
안 붙는다. 격자를 바꿔 재보니 답이 나왔다: 12분음표(셋잇단 8분) 격자엔 21~30% 붙는다.
자유 템포 탐색도 같은 곳을 가리켰다 — 109 BPM, 즉 146 × ¾. **브레이크다운이 셋잇단 느낌으로
돈다.** PLAN §6⑥ 이 요구한 "셋잇단·스윙 보존"이 이것이다. 창마다 두 격자를 다 맞추고 귀무
기준선을 각각 빼서, 12분 여유가 16분 여유보다 0.05 이상 크면 그 창은 셋잇단 구간이다.
그래서 그리드를 16분음표 목록이 아니라 **비트 목록**으로 걷고, 분할은 구간마다 다르게 얹는다.
비트 위상은 이전 창에서 예측한 비트에 가장 가까운 격자 점을 골라 이어 붙인다(연속성 우선,
첫 창만 센 온셋 투표). `main.ts` 가 `셋잇단 구간 12s — 63~67s, 71~79s` 로 찍는다.

**lag-3 flux** — 슈퍼소는 디튠된 오실레이터 수십 개라 프레임마다 빈 크기가 맥놀이로
출렁이고, 1프레임 차분은 상시 잡음 마루를 만든다. 직전 3프레임 평균 대비로 바꾸면
가라앉고(저역 ACF 1.9→2.6) 깨끗한 타격의 재현율·bias 는 그대로다.

**BPM 힌트 폴백** — 힌트 ±8% 안의 추정이 경계에 붙으면 진짜 값이 밖에 있다는 신호다.
자유 탐색으로 물러나고 경고한다. future-core 는 프롬프트 160, 실제 145.8 이었다.

## 난이도

같은 음원, 같은 온셋. `build.ts` 의 `PARAMS` 가 거른다.

| | easy | normal | hard |
|---|---|---|---|
| 그리드 | 8분음표 | 16분음표 | 16분음표 |
| 온셋 세기 (sf/thr) | ≥ 1.6 | ≥ 1.25 | ≥ 1.0 |
| 같은 타입 최소 간격 (비트) | 커서 1 / 클릭 1 / 스크롤 2 | ½ / ½ / 1 | ¼ / ¼ / ½ |
| 비트당 최대 노트 | 1 | 2 | 4 |
| 커서 예산 `v_max` (칸/초) | 2.5 | 4.5 | 7.5 |
| 클릭-커서 겹침 | 100ms 금지 | 60ms 금지 | 허용 |

간격을 초가 아니라 **비트 단위**로 두는 이유: 118 BPM 과 174 BPM 에서 같은 "음악적"
밀도가 되게 하기 위해서다. 절대 난이도 차이는 `songs.json` 의 `level`(1~10) 이 진다 —
DnB 의 easy 는 synthwave 의 normal 쯤 된다.

`v_max` 는 실측 대상이다 (PLAN §15). 지금 값은 추정치.

## 결정성

- 시드 = `hash(songHash | difficulty | generator)`. songHash 는 WAV 파일 바이트의 sha256
- 채보 파일은 `canonicalize()` 의 정규 직렬화 그대로라 **`sha256(파일) == chartHash`**
- `t` 는 정수 ms. 부동소수점이 들어가면 `canonicalize` 가 throw 한다
- 셀프테스트가 "같은 입력 → 같은 채보"와 "다른 곡 → 다른 배치"를 확인한다

알고리즘을 바꾸면 `GENERATOR` 를 올린다. 해시가 바뀌므로 새 채보 = 새 기록 슬롯이고
옛 기록은 오염되지 않는다 (PLAN §8).

## 귀로 검증

```bash
npm run chart -- song.wav --slug my-song --preview
# → tools/chartgen/work/my-song-hard.wav
```

원곡 위에 노트 타입별 소리를 얹는다: cursor 1.2kHz 톡, click 3kHz 틱, scroll 250Hz 툭.
**M3 의 목적은 이걸 듣고 "노트가 음악에 맞게 떨어지는가"를 확인하는 것이다** (PLAN §13).
이게 안 맞으면 나머지가 무의미하다.

`--dump` 를 주면 `work/<slug>-onsets.csv` 에 온셋 전체(시각·대역·비율)가 떨어진다.

## 셀프테스트

`selftest.ts` 가 150 BPM 합성 드럼(킥 1·3박, 스네어 2·4박, 햇 8분음표, 조용한 8박 인트로,
패드, 노이즈 바닥)을 만들어 정답과 대조한다. 확인하는 것:

- BPM ±0.5, 비트 위상 ±15ms
- 대역별 재현율·정밀도·검출 bias (bias 가 `DETECTION_OFFSET_SEC` 의 근거다)
- 채보 규칙 위반 0, 밀도 단조 증가, 결정성
- **드리프트 시나리오**: 150→154 BPM 램프에서 지역 BPM 추적, `beats` 오차 p90 < 20ms, 스냅 후 노트↔진짜 타격 p90 < 25ms

정밀도 바닥은 느슨하다. 스네어는 광대역이라 저역·고역에도 *정직하게* 잡히고, 그건
`build.ts` 의 겹침 규칙이 거른다. 여기서 잡는 건 "타격 하나가 여럿으로 쪼개지는" 회귀다.

`--wav` 를 주면 `work/` 에 합성 신호와 클릭 트랙을 써준다.

## 첫 실제 곡에서 배운 것

`future-core-1451544524` (ACE-Step, 프롬프트 160 BPM "four on the floor kick, clean transients"):

- 실제 BPM 145.8, 드리프트 3.8%. **프롬프트 BPM 은 희망사항이다.** `songs.json` 의 bpm 은 실측으로 쓴다
- 저역에 킥이 없다. 에너지의 90% 가 저역인데 비트 주기가 없다 — 베이스 벽이다. 스크롤 노트 0
- mid/high 는 지역 그리드에 65~71% 붙는다. 곡 앞 24초와 끝 16초는 90~100%, 중간(56~88초)은 50% 대 — 브레이크다운
- PLAN §6 의 "AI 생성 EDM 은 기계적으로 정확하다"는 **틀렸다.** 드리프트 추적 없이는 안 된다

곡을 고를 때 볼 것은 `main.ts` 가 찍는 대역 적합도 세 줄이다. low ✗ 면 스크롤이 없는 곡이고,
mid ✗ 면 버린다. "듣기 좋은가"와 "채보가 나오는가"는 다른 질문이다.

## 한계 (v2)

- **변박·급격한 템포 변화는 못 따라간다.** 8초 창 안에서 ±5% 까지만. 램프·미세 드리프트는 된다.
  브레이크다운이 통째로 다른 템포(예: 146 → 109)로 가면 셋잇단으로 읽힌다 — 결과 격자는 같다
- **다운비트를 모른다.** `beats` 의 어느 것이 마디 첫 박인지는 센 온셋 투표로 16분 위상만 고른다. 섹션 경계(8마디)에 마디 보장이 없다
- 셋잇단 구간의 신뢰도 여유는 21~30% 로 정박 구간(36~53%)보다 낮다. 격자가 "더 잘" 설명하는
  것이지 "잘" 설명하는 건 아니다. 귀로 확인 중. 스윙(셋잇단 중 가운데 점을 비우는 것)은 아직
  별도 격자로 두지 않았다 — 12분 격자가 스윙도 대충 받아준다
- 분할 후보가 16분과 12분뿐이다. 5연음·7연음, 6/8 박자는 없다
- 지배 대역 해소가 저역 잡음에 끌릴 수 있다. 킥 없는 곡에서 1000 개 넘는 저역 검출이 게이트로 걸러지긴 하지만, 그 전에 mid/high 의 동시 타격을 일부 흡수했을 수 있다 — 확인 필요
- 커서 배치가 랜덤이라 "아까 그거다" 하는 반복 인지가 없다 — M4
- `level` 은 nps 와 커서 속도로 만든 추정치. 손으로 고쳐도 된다
- `δ`·`α`·`v_max` 는 실제 곡 한 곡으로만 봤다 (PLAN §15). 곡이 쌓이면 다시 본다
